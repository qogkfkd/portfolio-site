# 작품 분류와 관련 파일 보기 설계

- 작성일: 2026-11-03
- 상태: 사용자 합의(구성은 A안, AI 작품 배지 이름은 "AI 협업")
- 작성: Claude (기획·설계), 구현 담당: Codex (승인된 계획만 실행)

## 1. 목적

이 사이트는 개발자 포트폴리오다. 방문자(특히 채용 담당자)가 다음을 바로 구분할 수 있어야 한다.

1. 작품을 직접 코딩으로 만들었는지, AI와 협업해 만들었는지
2. 기획자 역할도 했는지
3. 어떤 대회의 작품인지 보여 주는 관련 자료

### 성공 기준
- 홈의 카드와 작품 상세에서 개발 방식이 배지로 보인다. 직접 코딩이 더 눈에 띈다.
- 개발 방식으로 걸러 볼 수 있다.
- 대표작 영역에서 수상작이 먼저 나온다.
- PDF와 이미지 첨부파일은 브라우저에서 바로 볼 수 있고, 내려받기도 그대로 된다.
- 기존 작품과 기존 주소는 그대로 동작한다.

### 하지 않는 것
- 탭이나 구역으로 화면을 나누기: 직접 코딩 작품이 지금 하나뿐이다. 늘어나면 다시 본다.
- 기획을 위한 별도 페이지나 새 항목: 아래 3장처럼 기존 기능으로 보여 준다.
- hwp 미리 보기: 브라우저가 열 수 없다. PDF로 저장해 올린다.

## 2. 개발 방식

### 데이터
`works`에 `dev_method` 열을 더한다. 값은 `hand`(직접 코딩), `ai`(AI 협업), `NULL`(표시 안 함)이다. 기존 작품은 `NULL`로 시작한다.

```sql
ALTER TABLE works ADD COLUMN dev_method TEXT CHECK (dev_method IN ('hand', 'ai'));
```

### 화면
- **입력:** 작품 폼의 "팀과 역할" 구역에 "개발 방식" 선택(선택 안 함, 직접 코딩, AI 협업)을 둔다.
- **카드와 상세:** 태그 줄 맨 앞에 배지를 넣는다. 직접 코딩은 강조색을 채우고, AI 협업은 옅은 색으로 둔다.
- **관리자 목록:** 작품 줄에 글자로 보여 준다.
- **걸러 보기:** 주소 쿼리 `method=hand|ai`. 공개 작품에 실제로 있는 값만 선택지로 보여 주고, 하나도 없으면 칸을 숨긴다. 잘못된 값은 무시한다.

### 대표작 순서
대표작 영역은 수상작을 먼저, 그 안에서 기존 정렬(정렬 날짜 최신순)을 따른다. 전체 작품 목록의 순서는 바꾸지 않는다.

## 3. 기획 보여 주기 (코드 변경 없음)

- 작품의 "작업한 분야"에 `기획`, `개발`을 넣는다. 분야 걸러 보기로 기획한 작품만 볼 수 있다.
- 기획서는 첨부파일로 올린다. 폴더 이름이 묶음 제목이 되므로 `기획서` 폴더로 올린다.
- 대회 자료도 같은 방식으로 `대회 자료` 폴더로 올리고, 대회 공지는 링크(종류 "링크")로 넣는다.
- 소개글 앞부분에 "왜 이렇게 기획했는지"를 쓴다.

## 4. 관련 파일 보기

### 주소와 규칙
파일 주소에 `?v=view`를 붙이면 바로 보기로 준다.

| 파일 | 기본 주소 | `?v=view` |
|---|---|---|
| 첨부: PDF, jpg, png, webp, gif | 내려받기 | 브라우저에서 표시(`inline`) |
| 첨부: 그 밖의 형식 | 내려받기 | 그대로 내려받기 |
| 대표 이미지, 스크린샷, 프로필 사진 | 기존과 같음 | 기존과 같음 |

- 접근 규칙은 그대로다. 비공개 작품의 파일은 `?v=view`여도 방문자에게 404다.
- `Content-Type`은 허용 목록에 든 값일 때만 표시하고, svg와 html은 어떤 경우에도 표시하지 않는다.
- 첨부파일의 보안 머리글(`Content-Security-Policy: default-src 'none'; sandbox`, `X-Content-Type-Options: nosniff`)은 그대로 둔다.
  - 2026-11-03 시험: 설치된 Chrome에서 이 머리글을 둔 채 PDF와 이미지가 표시됐다.
  - 다른 브라우저는 시험하지 않았다. 표시가 안 되는 브라우저에서도 내려받기는 남는다.

### 화면
작품 상세의 첨부 목록에서 PDF와 이미지 줄에 "보기" 링크를 더한다. 새 탭으로 연다. 파일 이름을 누르면 기존처럼 내려받는다.

## 5. 검증

- **단위 테스트:** 개발 방식 파싱·저장·검증, 걸러 보기, 대표작 순서, 파일 보기 규칙(허용 형식, 비허용 형식, 비공개 404, 내려받기 유지).
- **브라우저 시험:** 배지, 개발 방식 걸러 보기, 수상작 우선, PDF "보기"와 hwp의 보기 없음.
- **배포 순서:** 원격 DB에 열을 먼저 더한 뒤 코드를 올린다. 열 추가는 기존 코드에 영향이 없다.
