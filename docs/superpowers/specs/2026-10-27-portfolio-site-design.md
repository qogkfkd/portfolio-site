# 개인 포트폴리오 사이트 설계

- 작성일: 2026-10-27
- 상태: 사용자 검토 대기
- 작성: Claude (기획·설계), 구현 담당: Codex (승인된 계획만 실행)

## 1. 목적과 범위

### 목적
본인의 대회 참가작과 작업물을 전시하는 사이트. 누구나 로그인 없이 볼 수 있고, 글쓰기·수정은 본인만 한다.

### 주 방문자
- 본인: 활동 기록 보관
- 지인·팀원: 링크로 공유받아 봄
- 채용 담당자: 지원서의 링크로 들어와 짧은 시간 안에 역량과 성과를 확인함

그래서 홈 첫 화면에서 대표작과 수상 내역이 바로 보여야 한다.

### 사용자 조건
- 코드 경험이 거의 없다. 구현과 유지보수는 Claude와 Codex가 맡는다.
- 운영비는 완전 무료여야 한다. 주소는 무료 `*.workers.dev`를 쓴다.
- 첨부파일 크기는 아직 모르므로 넉넉하게 설계한다.
- 사이트는 한국어로만 만든다.

### 하지 않는 것
댓글, 좋아요, 방문자 통계, 회원가입, 여러 관리자, 다국어, 블로그, 첨부 zip 자동 생성, 다크 모드, 설명 본문 안의 이미지 삽입(갤러리로 대신함). 개인 도메인은 지금 하지 않되, 나중에 연결할 수 있는 구조로 둔다.

## 2. 기술 구조

| 역할 | 선택 |
|---|---|
| 프레임워크 | Astro (서버 렌더링) + TypeScript, Cloudflare 어댑터 |
| 호스팅 | Cloudflare Workers (무료 요금제) |
| DB | Cloudflare D1 (SQLite) |
| 파일 저장소 | Cloudflare R2 (무료 10GB, 내려받기 트래픽 무료) |
| 관리자 화면의 움직이는 부분 | React 컴포넌트 (설명 편집기, 파일 업로드, 태그 입력) |
| 설명 편집기 | Tiptap 계열 서식 편집기 |
| 글꼴 | Pretendard (자체 호스팅) |
| 테스트 | Vitest (Workers 환경 + 로컬 D1/R2), Playwright (브라우저 흐름) |

선택 이유: Cloudflare 계정 하나로 호스팅, DB, 파일 저장소를 해결한다. 접속이 없어도 일시정지되지 않는다. 파일 저장소 무료 용량이 10GB로 넉넉하다. 비교했던 Vercel + Supabase는 무료 파일 저장소가 1GB이고 일주일 동안 접속이 없으면 서비스가 일시정지되어 제외했다.

방문자 화면의 핵심 기능(목록, 걸러 보기, 상세, 내려받기)은 JavaScript 없이도 동작하게 한다. 걸러 보기는 서버에서 처리한다. 갤러리 크게 보기만 작은 스크립트를 쓰는데, 스크립트가 없으면 이미지 링크로 열린다. React는 관리자 화면에만 쓴다.

## 3. 화면

### 3.1 방문자 화면

**홈 `/`**
1. 소개 영역: 이름, 한 줄 소개, 짧은 자기소개, 프로필 사진(있을 때), 연락처 버튼(이메일, GitHub, 기타 링크)
2. 대표작 영역: 공개된 대표작을 큰 카드로 보여준다. 대표작이 없으면 이 영역을 숨긴다.
3. 전체 작품 영역: 공개 작품의 카드 목록과 걸러 보기
   - 걸러 보기: 분야(하나 선택), 연도(하나 선택), 수상작만(켜기/끄기). 분야와 연도의 선택지는 공개 작품에 실제로 있는 값만 보여준다.
   - 조건은 주소 쿼리로 표현한다(`/?field=디자인&year=2025&award=1`). 거른 화면도 링크로 공유할 수 있다.
   - 조건에 맞는 작품이 없거나 공개 작품이 하나도 없으면 안내 문구를 보여준다.
   - 대표작은 대표작 영역과 전체 목록 양쪽에 모두 나온다.
4. 카드에 들어가는 것: 대표 이미지(작은 크기), 작품명, 한 줄 요약, 분야 태그, 대회명, 연도, 수상 배지

**작품 상세 `/works/{slug}`**
- 작품명, 대회명, 주최 기관, 참가일, 작업 기간, 분야 태그, 수상 배지
- 팀/개인(인원 수), 내 역할, 사용 기술 태그
- 대표 이미지와 스크린샷 갤러리(누르면 크게 보기)
- 설명 본문
- 링크 버튼. "영상" 종류의 링크가 유튜브 주소(`youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`)이면 본문 아래에 `youtube-nocookie.com` 퍼가기 영상으로 넣는다. 그 밖의 영상 주소는 버튼으로만 보여준다.
- 첨부파일 목록: 폴더 경로별로 묶어서 파일명과 크기를 보여주고, 파일마다 내려받기 링크를 둔다.
- 비어 있는 선택 항목은 표시하지 않는다.
- 비공개 작품: 방문자에게는 404다. 로그인한 관리자에게는 "비공개 미리보기" 띠를 붙여서 보여준다.

**404 페이지**: 홈으로 가는 링크가 있는 안내 페이지.

### 3.2 관리자 화면 (로그인 필요)

| 주소 | 내용 |
|---|---|
| `/admin/login` | 비밀번호 입력 |
| `/admin` | 작품 목록(작은 이미지, 작품명, 날짜, 공개 전환, 대표작 전환, 수정, 삭제), 저장 공간 사용량("10GB 중 n GB"), 로그아웃 |
| `/admin/works/new` | 새 작품 작성 |
| `/admin/works/{id}/edit` | 작품 수정, 파일 관리 |
| `/admin/profile` | 자기소개와 연락처 수정, 프로필 사진 |

- 삭제할 때는 확인 창을 띄운다. 함께 지워질 파일 수도 알려준다.
- 저장하지 않은 변경이 있는데 페이지를 떠나려 하면 경고한다.
- 파일 영역은 작품을 한 번 저장한 뒤에 열린다. 새 작품 화면에서는 "저장하면 파일을 올릴 수 있어요"라고 안내한다.
- 새 작품은 비공개로 저장된다.

### 3.3 디자인 방향
- 깔끔한 미니멀: 밝은 배경, 넓은 여백, 작품 이미지가 주인공
- 대표 이미지가 없는 카드는 기본 카드로 대신한다. 첫 번째 분야 이름으로 정해지는 색(6색 팔레트 중 하나, 같은 분야는 항상 같은 색) 바탕에 작품명을 넣는다.
- 화면 폭이 좁으면(모바일) 카드가 한 줄에 하나씩 나오고, 넓은 화면에서는 2~3개씩 나온다.

### 4.2 자기소개 항목
이름(필수), 한 줄 소개, 자기소개(여러 줄 글자), 프로필 사진, 이메일, GitHub 주소, 기타 링크 목록(이름, 주소). 처음 배포했을 때는 이름 "이름을 입력하세요"로 된 기본값 한 줄이 있다.

### 4.3 D1 테이블 (요약)

- `profile`: 행 하나(id = 1). 위 자기소개 항목, `updated_at`
- `works`: 위 작품 항목. 분야·기술·링크는 JSON 문자열 열로 둔다(작품 수가 수백 개 이하라 별도 테이블이 필요 없다). `is_public`, `is_featured`, `created_at`, `updated_at`
- `files`: `id`, `work_id`(프로필 사진이면 NULL), `kind`(`cover` | `gallery` | `attachment` | `avatar`), `r2_key`, `thumb_r2_key`(이미지에만 있음), `original_name`, `relative_path`(첨부 폴더 경로, 없으면 빈 값), `content_type`, `size_bytes`(썸네일 크기 포함), `sort_order`, `status`(`uploading` | `complete`), `upload_id`(R2 멀티파트 ID), `created_at`
  - 대표 이미지와 프로필 사진은 별도의 ID 열을 두지 않고 `kind`로 찾는다. 작품 하나에 `cover`는 최대 1개, `avatar`는 전체에서 최대 1개다.
- `login_attempts`: `ip`, `failed_count`, `locked_until`, `updated_at`

스키마는 wrangler D1 마이그레이션 SQL 파일로 관리한다.

## 5. 핵심 동작

### 5.1 로그인
- 관리자는 한 명이고 비밀번호 하나로 로그인한다.
- 비밀번호는 원문을 저장하지 않는다. PBKDF2-SHA256 해시(솔트 포함)를 Worker 비밀값 `ADMIN_PASSWORD_HASH`에 둔다. 해시를 만드는 로컬 명령(`npm run hash-password`)을 제공한다. Workers의 PBKDF2 반복 횟수 상한(100,000회)을 넘지 않는다.
- 로그인에 성공하면 만료 시각에 HMAC 서명을 붙인 쿠키를 준다. 서명 키는 비밀값 `SESSION_SECRET`이다. 쿠키 속성은 `HttpOnly`, `Secure`, `SameSite=Strict`, 유효 기간 7일이다. 로그아웃하면 쿠키를 지운다. `SESSION_SECRET`을 바꾸면 모든 로그인이 풀린다.
- 같은 IP(`CF-Connecting-IP`, 로컬 개발처럼 이 헤더가 없으면 `local`)에서 5번 연속 틀리면 15분 동안 로그인을 막는다. 성공하면 횟수를 초기화한다.
- `/admin/*`과 `/api/admin/*`은 미들웨어에서 쿠키를 검사한다. 로그인하지 않았으면 페이지는 `/admin/login`으로 보내고, API는 401을 돌려준다.
- 상태를 바꾸는 모든 요청(POST/PUT/PATCH/DELETE)은 `Origin` 헤더가 사이트 자신일 때만 받는다(CSRF 방어).
- 관리자 페이지에는 `X-Robots-Tag: noindex`를 붙이고, `robots.txt`에서 `/admin`을 막는다.

### 5.2 파일 업로드
- 모든 업로드는 Worker를 거쳐 R2 멀티파트 업로드로 처리한다. 순서는 시작 → 조각 업로드(10MiB) → 완료이고, 취소하거나 실패하면 중단 요청을 보낸다. 파일 하나는 순서대로 올리고, 여러 파일은 동시에 최대 3개까지 올린다. Workers 요청 본문 크기 제한(무료 100MB)을 조각 크기로 피한다.
- 제한: 파일 하나 최대 1GB. 저장 공간 전체 합계가 9.5GB(무료 10GB에서 여유분을 뺀 값, 설정 상수)를 넘게 되는 업로드는 시작 단계에서 거절한다. 합계는 `files`의 `size_bytes` 합으로 계산한다.
- 이미지(대표 이미지, 스크린샷, 프로필 사진)는 jpg, png, webp, gif만 받는다. 브라우저에서 긴 변 2000px WebP(표시용)와 긴 변 600px WebP(썸네일)로 줄여서 올린다. 원본이 그보다 작으면 키우지 않는다. gif는 움직임을 지키기 위해 원본 그대로 두고, 썸네일도 원본을 쓴다(`thumb_r2_key` = `r2_key`). svg는 받지 않는다.
- 첨부파일은 종류 제한 없이 원본 그대로 올린다. 폴더째 선택하는 버튼과 끌어다 놓기 모두 폴더 구조(`relative_path`)를 유지한다.
- 진행률을 파일마다 보여준다. 실패한 파일에는 "다시 시도" 버튼을 둔다.
- 관리자 목록 화면을 열 때마다 24시간 넘게 `uploading` 상태로 남은 기록을 중단 처리하고 지운다.
- 작품을 지우면 그 작품의 R2 객체와 `files` 기록을 모두 지운다. 파일 하나만 지울 수도 있다.

### 5.3 설명 서식 정리
저장할 때 서버에서 허용 목록 방식으로 HTML을 정리한다.
- 허용 태그: `p`, `h2`, `h3`, `strong`, `em`, `u`, `s`, `ul`, `ol`, `li`, `a`, `blockquote`, `code`, `pre`, `br`, `hr`
- `a`에는 `href`만 남기고, `http:`, `https:`, `mailto:`만 허용한다. 화면에 낼 때 `rel="noopener noreferrer"`와 `target="_blank"`를 붙인다.
- 나머지 태그는 껍데기만 벗기고 안의 글자는 남긴다. 단, `script`와 `style`은 내용까지 지운다. 모든 속성은 지운다.
- 쓰는 라이브러리가 Workers 환경에서 동작하는지는 구현 계획 단계에서 확인한다.

### 5.4 파일 제공
- 주소 `/files/{fileId}/{원본 파일명}`(썸네일은 `?v=thumb`)
- 접근 규칙: 작품이 공개 상태이거나 관리자로 로그인한 경우에만 내려준다. 그 밖에는 404다. 프로필 사진은 항상 공개한다. `uploading` 상태인 파일도 404다.
- 이미지는 화면에 바로 표시한다(`inline`). 첨부파일은 `Content-Disposition: attachment`로 내려받게 하고, 한글 파일명은 RFC 5987 방식(`filename*=UTF-8''...`)으로 보낸다.
- 모든 파일에 `X-Content-Type-Options: nosniff`를 붙인다.
- `Range` 요청을 지원해서 큰 파일을 이어받거나 영상을 재생할 수 있게 한다.
- 공개 파일에는 `Cache-Control: public, max-age=86400`을, 관리자 전용으로 내려준 파일에는 `private, no-store`를 붙인다.

### 5.5 링크 미리보기 (Open Graph)
- 홈: 이름, 한 줄 소개, 프로필 사진
- 작품 상세: 작품명, 한 줄 요약, 대표 이미지(표시용)의 절대 주소
- `og:title`, `og:description`, `og:image`, `og:url`, `twitter:card=summary_large_image`를 넣는다.

### 5.6 오류 처리
- 입력 검사는 브라우저와 서버 양쪽에서 한다. 오류 문구는 한국어로 해당 칸 옆에 보여준다.
- 서버 오류가 나면 관리자 화면에는 "저장하지 못했어요. 잠시 후 다시 시도해 주세요" 같은 안내를 띄운다. 입력한 내용은 지우지 않는다.
- 방문자 화면에서 오류가 나면 일반 오류 페이지를 보여주고, 자세한 내용은 Worker 로그에만 남긴다.

## 6. 검증

### 6.1 자동 테스트 (Vitest, Workers 환경)
- 비밀번호 해시 검증, 쿠키 서명과 만료, 5회 실패 잠금과 15분 뒤 해제
- 로그인하지 않은 상태에서 관리자 API 401, 다른 출처의 `Origin`이면 거절
- 정렬 날짜 우선순위, 걸러 보기(분야, 연도, 수상)
- slug 생성(한글, 특수문자, 중복)
- 서식 정리(허용 태그 유지, `script` 제거, `javascript:` 링크 제거)
- 파일 제공 규칙(공개/비공개/관리자/uploading), 한글 파일명 헤더, Range 응답
- 업로드 흐름(시작/조각/완료/중단), 1GB 초과 거절, 전체 용량 초과 거절
- 작품을 삭제하면 R2 객체도 삭제됨

### 6.2 브라우저 흐름 (Playwright, 로컬 D1/R2)
1. 틀린 비밀번호를 넣으면 실패하고, 맞는 비밀번호로 로그인된다.
2. 필수 항목 없이 저장하면 오류가 표시된다.
3. 작품을 저장한 뒤 대표 이미지, 스크린샷, 첨부 폴더를 올린다.
4. 공개하기 전에는 로그아웃한 방문자에게 홈 목록에 없고, 상세 페이지와 첨부 주소가 404다.
5. 공개한 뒤에는 방문자에게 홈, 상세, 첨부 내려받기가 모두 된다.
6. 걸러 보기가 동작한다.
7. 작품을 지우면 상세 페이지와 파일 주소가 404가 된다.

### 6.3 화면 확인
모바일(375px)과 데스크톱(1280px) 폭에서 홈, 상세, 관리자 폼을 실제 브라우저로 보고 깨지는 곳이 없는지 확인한다.

## 7. 배포와 운영

- 주소: `https://{worker 이름}.{계정 하위 도메인}.workers.dev`
- 사용자가 직접 할 일(협업 규칙상 Codex는 로그인과 배포를 하지 않는다): Cloudflare 가입, R2 활성화(카드 등록을 요구할 수 있음), `wrangler login`, D1/R2 생성, 비밀값 등록, 원격 마이그레이션 적용, 배포. 이 과정을 순서대로 따라 할 수 있는 한국어 안내서 `docs/배포-안내.md`를 함께 만든다.
- 빌드·테스트·배포 명령은 저장소 루트 `AGENTS.md` 한 곳에 적는다.

## 8. 완료 기준
1. 방문자가 로그인 없이 홈과 공개 작품 상세를 볼 수 있다.
2. 관리자가 로그인해서 작품을 작성, 수정, 삭제, 공개 전환, 대표작 지정할 수 있다. 자기소개도 고칠 수 있다.
3. 필수 항목(작품명, 분야, 설명)이 없으면 저장되지 않는다.
4. 이미지와 첨부파일(폴더 포함)을 올릴 수 있고, 1GB 제한과 용량 표시가 동작한다.
5. 비공개 작품과 그 파일은 방문자에게 404다.
6. 분야, 연도, 수상 걸러 보기가 동작한다.
7. 작품 링크를 공유하면 미리보기 정보(OG 태그)가 들어 있다.
8. 6.1과 6.2의 테스트가 모두 통과하고, 6.3의 화면 확인을 마쳤다.
9. 안내서대로 따라 하면 workers.dev 주소로 배포할 수 있다.

## 9. 구현 계획 단계에서 확인할 것
- Astro, Cloudflare 어댑터, wrangler의 현재 안정 버전과 D1/R2 바인딩을 쓰는 방법
- 서식 정리 라이브러리와 Tiptap이 Workers와 Astro 환경에서 동작하는지
- R2 멀티파트 업로드 API의 조각 크기 조건(마지막 조각을 빼고 모두 같은 크기, 최소 5MiB)
- D1 무료 요금제의 복구 기능(Time Travel) 보관 기간. 백업 기능을 따로 만들지는 이 결과를 보고 정한다.
- R2를 켤 때 카드 등록이 필요한지는 사용자가 가입하면서 확인한다.

## 10. 구현 순서
한 번에 다 만들지 않고 단계별로 계획 파일을 나눈다. 단계마다 Codex가 구현하고 Claude가 리뷰한 뒤 다음 단계로 넘어간다.

1. **기반과 방문자 화면**: 프로젝트 생성, D1 스키마, 시드 데이터, 홈(걸러 보기 포함), 작품 상세, 404, OG 태그, 디자인
2. **로그인과 작품 관리**: 로그인과 보안(5.1), 작품 작성·수정·삭제·공개·대표작, 서식 편집기와 정리(5.3), 자기소개 수정
3. **파일**: 업로드(5.2), 파일 제공(5.4), 갤러리와 첨부 목록 표시, 용량 표시
4. **마무리와 배포 준비**: 브라우저 흐름 테스트(6.2), 화면 확인(6.3), `docs/배포-안내.md`, `AGENTS.md`
